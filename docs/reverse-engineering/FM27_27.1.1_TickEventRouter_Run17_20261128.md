## 2. 0xE5C4C0 是按消息类型/对象 ID 分派 match 回调的事件路由器

反编译中的关键结构：

- 从输入消息 `param_2+0x0C` 读取 32-bit message type。
- 从 `param_1[1]` 到 `param_1[2]` 遍历已注册/订阅对象数组（entry stride 16 bytes）。
- 以 entry 对象 `+0x140` 与消息 `param_2+0x10` 的对象 ID 匹配。
- 对匹配对象执行引用计数加减及对应 handler 分派。
- 至少两个消息分支触发 `0x28C1020`：
  - message type `0x6D75636D`：传入消息中的 tick/time 值，调用 `0x28C1020(lVar10, uVar3)`；
  - message type `0x73637373`：按消息 subtype bitmask 过滤后，调用 `0x28C1020(lVar10, iVar4)`。
- 同一 router 还会调用 `0x28C1C20`、`0x28C1E60`、`0x28C1FB0`、`0x28C2100`、`0x28C4250` 等不同消息处理函数。

**准确定位：**`0xE5C4C0` 是 match 事件/订阅对象路由器；它把一条携带 tick/time 参数的消息投递给 `0x28C1020`。它不是已证明的最顶层游戏模拟器入口，也不是球物理函数。
