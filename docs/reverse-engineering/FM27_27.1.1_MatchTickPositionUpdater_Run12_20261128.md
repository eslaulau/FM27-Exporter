## 1. 0x42D3910 是 match-level update / event dispatch routine

反编译显示：

- 函数参数 param_1 是 match-level context；多次读取双方 team object +0x15380/+0x15388、双方 player arrays（team +0x138、count +0x72E）。
- 直接读取当前 match tick +0x154EC，并更新/比较 +0x154C4/+0x154C8 等时间窗口字段。
- 清理并构建多个 match update 输出/事件队列字段 +0x12EE0..+0x12F30、+0x13E40。
- 调用多个 team/player 更新 helper；会遍历两边球员槽，根据 player 状态（如 +0x23C6）更新球员状态/计时字段。
- 按两队活动/待更新计数、当前 tick 和 match phase 分支处理一个队或另一个队的更新；将事件类型 0x11/0x12 等写入 match event/update record buffer。
- 在主要更新分支中直接调用 0x2AFB290；在另一个分支会调用 0x42D58E0。

因此，0x42D3910 不只是与 match 结构偏移相似的普通 helper：它读取 match tick、双队、球员数组和更新事件队列，并按当前时序控制球员状态更新，是一个 match-level tick/update routine。

## 2. 0x42D58E0 是它的子阶段，也直接调用位置/运动状态更新器

机器 xref 和反编译确认：

- 0x42D3910 在 call site 0x42D45FF 调用 0x42D58E0。
- 0x42D58E0 再在 call site 0x42D5BEB 调用 0x2AFB290。
- 0x42D58E0 自己读取 match tick +0x154EC、当前 player/team 对象和调度条件；更新 match event queue 中的记录（事件 type 0x13）、当前 tick 和记账字段，并设置后续更新窗口 +0x154C4/+0x154C8。
- 它在更新分支中调用 0x2AFB290，随后对 +0x23C6 == 1 的 player 槽调用时间/历史样本更新 helper 0x19E0。

所以这两个 position-writer callers 不是互不相关的调用点：0x42D58E0 本身就是 0x42D3910 的子阶段。

## 3. 现在可以确认的更新链

## 6. Run #16：0x28C1020 是按目标 tick 驱动状态机的上层循环

Movement Commit Run #16（Workflow `46138521235`，Artifact `15259919842`）新增 caller 伪代码显示，函数 `0x28C1020` 在 call site `0x28C1060` 调用 `0x47C5350)。

### 0x28C1020 的 tick-advance 逻辑

函数入口：
- 从调用上下文 `param_1+0xA0`（伪代码中 `param_1[0x20]`）取得 match object；
- 读取 match 当前 tick `MATCH+0x154EC`；
- 若传入目标 tick `param_2` 不大于当前 tick，直接返回；
- 如果 match stop/error flag `MATCH+0x15500 & 4` 尚未置位，则循环：
  1. 比较目标 tick 与当前 `MATCH+0x154EC`；
  2. 调用 `0x47C5350(match, 0, -1)`；
  3. 检查 stop/error flag；
  4. 在特定当前状态下调用 `0x47C33F0` 后处理；
  5. 直到目标 tick 已推进或 stop/error flag 置位。
- 循环后处理 match event/任务队列 `MATCH+0x14EA0`，并更新对外 tick/UI 时间字段。

这证明 `0x28C1020` 是一个**按目标 tick 推进比赛状态机的循环入口/包装器**，不是单纯 UI 计时器：它直接调用状态机并读取/处理 match 自身事件队列。

### 0x47C5350 的状态机状态转移（证据：反编译 switch）

- `MATCH+0x1556C`：当前状态；
- `MATCH+0x1556B`：本轮状态处理后返回的下一状态；
- 当状态改变时，先根据旧状态执行离开阶段 helper，再按新状态调用进入阶段 helper；
- 然后按当前状态执行实际处理分支：
  - state 1：`0x47C58C0)；
  - **state 2：`0x42D3910)**；
  - state 3：`0x53380)；
  - state 4：`0x7EB10)；
  - state 5：推进 `+0x154EC) / `+0x15464` 计数，并滚动 match 更新记录缓冲区。
- 该状态机还会处理 `MATCH+0x15588` 注册对象/订阅者的回调，更新 `+0x13E40` 计数与队列。
