## 1. OOP scoring provider is a concrete engine subsystem

RTTI/vtable data identifies `simatchshared::scoring::MATCH_OOP_SCORING_PROVIDER` with two child scoring objects:
- `OOP_ATTRIBUTE`, vtable `0x512E3C8`, evaluator/config reader at RVA `0x11FA50`;
- `PITCH_PROXIMITY_SCORE`, vtable `0x512E2A8`, evaluator/config reader at RVA `0x11E260`.

The provider initializer at RVA `0x4BF9BA0` allocates both objects and initializes them. The OOP attribute path reads structured data keyed by the literal strings `RolePosition` and `ATTRIBUTES`. The pitch-proximity path reads data keyed by `Position` and `Role`. Both methods produce structured numeric outputs rather than a simple Boolean flag.

This proves the native engine has a configurable OOP scoring subsystem that combines role/position context with attribute data and a separate pitch-proximity score. It is a high-value route into the calculations that rank or evaluate OOP positioning.

**Limit:** this pass has not yet located the complete virtual-call consumer or reconstructed the final formula/normalization. It is not yet valid to say which attribute has what weight, or that the score directly moves a player.

## 2. Pressing manager A performs phase-aware zone and distance gating

At RVA `0x47FA990`, the function:
- selects a match-slice position record and normalizes coordinates against pitch dimensions;
- quantizes the location into a coarse pitch grid and mirrors/transforms the cell based on side orientation;
- branches on the resulting grid cell;
- checks phase-specific PI records, including bit `0x10`;
- scans teammates/opponents with that bit, compares squared spatial distances, and derives normalized direction/projection vectors;
- writes a 4D spatial output through the caller-provided pointer.

This is direct evidence that pressing/cover geometry is conditioned by pitch zone, active phase PI records and relative distances. The function does not reduce to a single team pressing intensity scalar.

The other two implementations (`0x4996D50`, `0x4997910`) also calculate spatial targets using ball/player reference positions, opponent half-space scans, and tactical-mode bits at `+0x18D0`. Their exact output consumers remain to be traced.
